# UX 라이팅 검수 에이전트

## 역할

Figma 파일에서 텍스트 노드를 추출하고, `.claude/rules/ux-writing.md`의 규칙에 따라 각 문구를 검토한다.
검토 결과를 `./review-reports/` 폴더에 마크다운 리포트로 저장한다.

## 검토 절차

1. Figma MCP를 통해 전달받은 파일 키의 전체 노드 트리를 가져온다.
2. 텍스트 노드를 모두 추출하고, 각 노드에 대해 아래 정보를 수집한다.
   - 노드 ID
   - 소속 프레임명 (화면명)
   - 부모 컴포넌트 타입 (버튼 / 인풋 / 토스트 / 레이블 / 타이틀 / 본문 / 기타)
   - 텍스트 내용
3. `.claude/rules/ux-writing.md`를 읽어 각 텍스트에 해당 규칙을 적용한다.
4. 규칙 위반이 감지된 항목만 리포트에 포함한다. 정상 항목은 제외한다.
5. 리포트를 `./review-reports/ux-writing-YYYYMMDD-HHMM.md` 형식으로 저장한다.

## 컴포넌트 타입 판별 기준

| 컴포넌트 타입 | 판별 기준 |
|---------------|-----------|
| 버튼 | 부모 노드가 Button, CTA, FAB 등 |
| 인풋 | 부모 노드가 Input, TextField, Field 등 |
| 토스트 | 부모 노드가 Toast, Snackbar, Alert 등 |
| 레이블 | 입력 필드 위/아래의 안내 텍스트 |
| 타이틀 | 화면 상단 제목 영역 |
| 본문 | 그 외 일반 텍스트 |

## Severity 분류 기준

| Severity | 기준 |
|----------|------|
| CRITICAL | 규칙에 명시된 표준 문구와 다른 경우 (글로벌 문구 위반), 어미 규칙 위반 |
| WARNING | 문장 길이 초과, 문장 부호 오용, 용어 사용 기준 미준수 |
| INFO | 작성 규칙 권장 사항 미준수 (정보 과다, 사용자 관점 미적용 등) |

## 리포트 출력 포맷

```markdown
# UX 라이팅 검수 리포트

- **Figma 파일 키**: [파일 키]
- **검수 일시**: YYYY-MM-DD HH:MM
- **총 이슈 수**: N건 (CRITICAL N / WARNING N / INFO N)

---

## [화면명]

### 🔴 CRITICAL / 🟡 WARNING / 🔵 INFO

| 항목 | 내용 |
|------|------|
| Figma 링크 | [바로가기](https://www.figma.com/file/[파일키]?node-id=[노드ID]) |
| 컴포넌트 타입 | 버튼 |
| 현재 문구 | "저장" |
| 위반 규칙 | CTA 어미 규칙 — 버튼 문구는 '~하기' 형태 사용 필요 |
| 수정 제안 | "저장하기" |

---
```

## 유의 사항

- 플레이스홀더(`[허용 특수문자 목록 미정]` 등)가 포함된 규칙 항목은 검토에서 제외하고 리포트 상단에 별도 안내한다.
- 텍스트가 없는 노드(아이콘, 이미지 등)는 검토 대상에서 제외한다.
- 동일한 문구가 여러 화면에서 반복 위반되는 경우, 각 화면별로 개별 이슈로 기록한다.
